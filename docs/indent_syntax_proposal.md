# 言律语言缩进语法设计建议

## 当前语法 vs Python风格语法

### 当前语法(需要"结束"关键字):

```
如果 条件 成立 则
    输出 "条件为真"
    输出 "执行完成"
结束

循环 5 次 执行
    定义 变量 x 为 10
    输出 x
结束

函数 加法 参数 a b
    定义 变量 result 为 a + b
    返回 result
结束
```

### Python风格语法(基于缩进):

```
如果 条件 成立 则
    输出 "条件为真"
    输出 "执行完成"

循环 5 次 执行
    定义 变量 x 为 10
    输出 x

函数 加法 参数 a b
    定义 变量 result 为 a + b
    返回 result
```

## 实现方案

### 方案1: 完全基于缩进(推荐)

**优点:**
- 代码更简洁,不需要"结束"关键字
- 与Python语法一致,学习成本低
- 强制良好的代码风格

**实现步骤:**
1. 词法分析器记录每行的缩进级别
2. 解释器根据缩进级别判断代码块结束
3. 移除"结束"关键字或将其设为可选

**示例:**
```
如果 x 大于 0 则
    输出 "正数"
    如果 x 大于 10 则
        输出 "大于10"
    输出 "处理完成"
输出 "程序结束"
```

### 方案2: 混合模式(兼容性更好)

**优点:**
- 向后兼容现有代码
- 用户可以选择使用缩进或"结束"
- 渐进式迁移

**实现:**
- 如果检测到"结束"关键字,使用旧语法
- 如果没有"结束",使用缩进判断

### 方案3: 冒号语法(更接近Python)

**示例:**
```
如果 x 大于 0:
    输出 "正数"

循环 5 次:
    输出 "循环"

函数 加法(a, b):
    返回 a + b
```

### 2. 解释器修改

```python
def _execute_if(self, tokens, i):
    # 找到"则"关键字
    # 根据缩进级别确定代码块范围
    start_indent = tokens[i].indent
    block_end = find_block_end(tokens, i, start_indent)
    # 执行代码块
    ...

def find_block_end(tokens, start, base_indent):
    """找到缩进级别降低的位置"""
    for i in range(start, len(tokens)):
        if tokens[i].indent < base_indent:
            return i
    return len(tokens)
```

### 3. 语法规则

**缩进规则:**
- 使用4个空格作为标准缩进(与Python一致)
- 代码块内的代码必须比块首行多一级缩进
- 代码块结束当缩进级别降低时

**关键字修改:**
- "则"后面直接换行,开始缩进块
- "执行"后面直接换行,开始缩进块
- "结束"变为可选关键字

## 迁移策略

### 阶段1: 支持两种语法(当前)
- 保持现有"结束"关键字语法
- 添加缩进语法支持

### 阶段2: 推荐新语法
- 文档推荐使用缩进语法
- "结束"关键字标记为deprecated

### 阶段3: 默认缩进语法
- 默认使用缩进语法
- "结束"关键字完全移除或仅用于特殊情况

## 示例对比

### 条件语句

**旧语法:**
```
如果 x 大于 0 则
    输出 "正数"
否则
    输出 "非正数"
结束
```

**新语法:**
```
如果 x 大于 0 则
    输出 "正数"
否则
    输出 "非正数"
```

### 循环语句

**旧语法:**
```
循环 10 次 执行
    定义 变量 i 为 0
    输出 i
结束
```

**新语法:**
```
循环 10 次 执行
    定义 变量 i 为 0
    输出 i
```

### 函数定义

**旧语法:**
```
函数 阶乘 参数 n
    如果 n 小于等于 1 则
        返回 1
    结束
    返回 n * 阶乘(n-1)
结束
```

**新语法:**
```
函数 阶乘 参数 n
    如果 n 小于等于 1 则
        返回 1
    返回 n * 阶乘(n-1)
```

## 优势总结

1. **代码更简洁**: 减少20-30%的代码量
2. **学习成本低**: Python用户无需学习新语法
3. **可读性强**: 缩进直观显示代码结构
4. **强制规范**: 强制良好的代码风格
5. **编辑器友好**: 现代编辑器自动处理缩进

## 建议

**推荐实现方案1(完全基于缩进):**
- 这是现代编程语言的趋势
- Python、YAML、CoffeeScript等都采用缩进语法
- 用户体验最佳

**实现优先级:**
1. 先实现缩进检测和记录
2. 修改解释器支持缩进判断
3. 更新文档和示例
4. 逐步迁移现有代码

这个改进将使言律语言更加现代化和易用!
